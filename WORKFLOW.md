# Workflow — v6.3.1

`config/pipeline.json` is the executable workflow. This page is only its human-readable summary.

| Order | Stage | Owner | Result |
|---|---|---|---|
| 1 | Definition | 00 | objective, audience, action, scope and project config |
| 2 | Research | 01 | current evidence, reference principles and constraints |
| 3 | Content architecture | 02 | selected landing flow, copy, claims and primary/utility scene map |
| 4 | Direction divergence | 03 | project-specific premium bar and three physically distinct `DIR-*` territories |
| 5 | Independent direction review | 07 | isolated comparison and one selected territory or `REVISE` |
| 6 | Creative master | 03 | one generated `AM-*`, one user confirmation and binding design genome |
| 7 | Visual experience | 04 | scene grammar, high-value challenge, derived foundations, responsive UI and page rhythm |
| 8 | Independent design review | 07 | rendered findings |
| 9 | Technology + structural build | 06 | selected stack, executable structure and desktop/mobile renders |
| 10 | Media decision & handoff | 05 | render diagnosis, per-scene image decisions, external `IH-*` briefs, returned-asset validation and placement map |
| 11 | Integration | 06 | final landing with real media and fallbacks |
| 12 | Independent build review | 07 | final findings on the executable landing |
| 13 | Release | 00 | verified handoff and reusable design fingerprint |

A stage starts only when its pipeline entry conditions pass. A review finding returns to the owner; it does not restart unrelated stages. Each stage receives one corrective pass before stopping with preserved work.
