# System audit — v6.5.0

Date: 2026-08-28
Scope: conditional spatial experience and harness enforcement

## Finding

The system classified real 3D honestly and required external provenance, but the medium could be finalized after technology selection. It lacked one buildable contract connecting a spatial direction to camera/object/light states and state-specific runtime review.

## Correction

G3 now owns the comparison of flat, layered, rendered and interactive media over the same narrative job. Technology consumes the selected mode and runs a bounded physical spike only for interactive 3D. G4 converts the frozen mode into semantic `SPT-*` states, one resource/loading policy, real provenance, implementation and digest-bound QA.

The harness routes the conditional method in headless and chat modes. It validates G3 and G4 after their independent reviews and blocks technology selection, production planning or release when the relevant spatial contract is incomplete.

## KEEP

- Eight agents, six gates, thirteen stages and the existing project artifacts.
- `effect-selection.md` as the general authority for mechanism eligibility.
- `3D production provenance` as the sole source for tool, asset/runtime, rights, integration and fallback.
- Technology chosen for the approved design, including the simplest viable alternative.

## IMPROVE

- Validate the first managed interactive-3D landing against real low-power mobile hardware, not only browser emulation.
- Revisit runtime and asset budgets from measured project evidence without turning one production's limits into universal defaults.

## ADD

- One progressively loaded `spatial-experience.md` method.
- A G3 modality comparison and independent physical review.
- One physical runtime spike for selected interactive 3D.
- Semantic spatial storyboard states, loading/low-power/failure policy and state traversal.
- Deterministic validators plus six regression tests, including authority uniqueness.

## REMOVE

- Runtime selection before the spatial medium has design approval.
- Fixed stacks, mandatory full-viewport canvases and executor-specific architecture.
- Fixed scroll percentages as QA coverage.
- Open-ended browser correction loops and faux 3D as a cheaper substitute.

## Scenario verdicts

- “Premium” without a project-specific spatial reason: `NOT_ACTIVATED`.
- Interactive 3D without comparison, review or physical spike: `BLOCKED`.
- Spatial production without `SPT-*` states or fallbacks: `BLOCKED`.
- Interactive state without desktop/mobile digest-bound evidence: `BLOCKED`.
- Antigravity, Codex or Cursor used only as executor: `ALLOWED`, never treated as runtime proof.

## Verification

System, architecture, harness, delivery, packaging and semantic validators pass. All 161 tests pass, including six new spatial-contract cases.

## Result

PASS. Spatial work is now a conditional, ordered and enforceable modality inside the existing landing pipeline rather than another agent system.

After one managed interactive-3D landing produces real state traversal evidence on desktop and mobile.
