# Spatial experience

Use this method only when a project-specific object, material, transformation, place or viewpoint makes spatial treatment a credible candidate. “Premium”, “immersive”, “Awwwards” or a desire for spectacle are not sufficient triggers.

This is one conditional contract distributed across existing owners. It does not create another pipeline, agent, gate or design artifact.

## A. Select the medium in G3

04 compares the same narrative job and composition as `FLAT_2D`, `LAYERED_2D`, `RENDERED_3D` and `INTERACTIVE_3D`. Rendered 3D may omit the interactive candidate only when interaction has no plausible relationship to the job. Compare observable gain, need for viewpoint/manipulation, mobile and performance cost, and fallback equivalence.

Select the least complex medium that preserves the gain. `INTERACTIVE_3D` is valid only when viewpoint, manipulation or continuous spatial state changes add meaning that a render or independent 2D layers cannot preserve. Record the decision once in `visual-system.md#Spatial modality decision`; later stages consume it without reopening it.

07 reviews the comparison on physical evidence before G3 closes. It rejects a semantic justification without a visible advantage, generic spectacle, faux volume and a selected result whose simpler fallback is perceptually equivalent.

## B. Select technology after the medium

06 does not choose a 3D stack before G3. When `INTERACTIVE_3D` wins, compare the simplest viable runtime with at least one credible alternative inside the existing technology options. A contained viewer, vanilla Three.js, React Three Fiber, Spline or another current runtime are candidates, not defaults.

Run one bounded risk spike before committing the architecture. Prove asset loading, one representative state, HTML legibility, mobile/low-power behavior and the static fallback. Antigravity, Codex, Cursor or another coding environment may execute and inspect the work; none is the shipped runtime or a project dependency merely because it orchestrates the work.

## C. Produce the spatial contract in G4

05 converts the selected modality into spatial states in `production-plan.md#Spatial experience contract`. Each `SPT-*` state owns one narrative change and specifies scene, input, camera, object/material/light, HTML relationship, transition, mobile/reduced-motion/failure fallback and intended evidence. Do not describe scroll percentages when a semantic trigger or state boundary is available.

Keep one asset/runtime budget and loading policy for the complete spatial mechanism. The existing `3D production provenance` table remains the sole source for authoring tool, real asset/runtime, rights, integration marker and fallback; do not duplicate those facts in the storyboard.

CSS/SVG gradients, shadows, perspective and overlapping shapes remain 2D. When real 3D is selected, source or author real models/scenes through an identified external route. When it is not selected, resolve the idea confidently in 2D instead of imitating inexpensive 3D.

## D. Integrate without flattening the landing

06 implements the approved `SPT-*` states and keeps semantic copy in HTML unless the design explicitly requires otherwise. Loading failure, low-power devices, mobile and `prefers-reduced-motion` receive deliberate behavior that preserves the message and primary action. A WebGL canvas may be contained or full viewport; its size follows the selected experience rather than a stack convention.

The normal harness limits govern retries. Spatial production does not create an open-ended browser-fix loop or extra correction allowance.

## E. Verify semantic states

07 traverses every `SPT-*` state on desktop and mobile using unique physical evidence tied to the current implementation digest. Review direction fidelity, HTML legibility, material/light coherence, asset integrity and fallback equivalence. Interactive 3D additionally requires camera continuity, absence of object intersections and acceptable runtime smoothness.

Review the named states, not fixed 0/20/40/60/80/100 scroll captures. Report findings to the owning agent; the reviewer does not redesign or silently fix the scene.
