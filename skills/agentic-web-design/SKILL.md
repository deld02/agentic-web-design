# Agentic Web Design

## Execution lock — check before any design work

When the harness MCP is available, it is the canonical chat runtime. Call `start_landing` and execute only the returned `stage_packet`. The packet already contains the active specialist contract, required project inputs, current writable artifact, stage-specific methods and automatic capabilities. Load a conditional capability with `get_guidance` only when its declared trigger is present. Never reconstruct the system from GitHub or edit `status.json`; the harness embodies agent 00 and owns every transition.

Landing creation is valid only in one of two harness-managed modes:

- `HEADLESS_MANAGED`: `tools/evaluation_harness.py run` launched the executor and exposes `HARNESS_RUN_DIR`, `HARNESS_PROJECT_DIR`, `HARNESS_STAGE`, `HARNESS_AGENT` and `HARNESS_MODE`.
- `CHAT_INTERACTIVE`: when the current ChatGPT environment has Python/files but no invocable model CLI, run `chat-start`, complete only the returned stage and call `chat-next` before doing anything from the next stage. The harness validates and advances the same pipeline; do not use `record` or fabricate events.

If neither mode is active, the session is `UNMANAGED`. You may inspect, explain or audit, but must not build HTML, generate a substitute design manually or describe the result as an Agentic Web Design execution. If Python execution is available, start `CHAT_INTERACTIVE` instead of stopping merely because an external CLI is unavailable.

Before research or design, show the user the managed bootstrap values returned by the harness: execution mode, run ID and directory, project directory, active stage, agent and mode. Absence of this preflight means `AGENTIC WEB DESIGN: UNMANAGED` and work stops.

During `creative-master`, follow the run's versioned contract. In `evidence-led-v2`, choose PROOF_MODE for the creative uncertainty and deliver a physical capture plus PROOF_SOURCE; executable studies can be built under `evidence/proof/` and captured with `render_landing`. Only GENERATED_IMAGE requires real generation and its receipt. Legacy contracts retain their generated artistic master. Imports are not proof of generation; prompts and declarations are not physical proofs. The historical `AM-*` ID names exploratory evidence, not a promised hero layout; reviewed G3 `CMP-*` governs implementation.

Use `config/pipeline.json` as the execution authority. Outside MCP, create a project with `tools/new_project.py` when needed, then load only its current artifacts, the active agent contract and the method linked there. Do not reconstruct the whole system in context.

At every stage, read the capability router path supplied by the harness. Apply and log every `core + automatic` capability listed for that exact stage; evaluate conditional candidates only by their registered trigger. `chat-next` and the headless stage validator block missing activations, so a handwritten substitute or an unlogged claim is not a completed stage.

The essential path is:

1. Compile the project context before looking for a style: business, action, audience sophistication, trust, human presence, authority/warmth, technicality, experimental tolerance, locality, proof, narrative, emotion and mobile importance. Recalibrate visual quality from current live websites for every project using five physical lenses: direct, adjacent, frontier, strong simple and saturated/overused. Evidence older than 30 days is stale. Compare prior design fingerprints when available.
2. Define at least two content/landing flows, then run the structural interchangeability challenge before selection. Reject the default category sequence when sections could be exchanged without changing meaning. For the selected flow, build the per-scene Experience Spine in `content-architecture.md`; it defines the visitor's semantic progression without prescribing visuals or effects.
3. Define project-specific excellence from G1, then create two to four physical DIR territories according to uncertainty. Compare distinct relationships, not palette swaps. 07 selects or returns REVISE; 03 never approves its route.
4. Produce one AM creative proof in the mode required by the active contract. Its genome contains translation hypotheses, not binding web foundations. It remains exploratory evidence and never ships; preserve packet checkpoint policy.
5. Probe opening, explanation/proof and action/closure with real content in desktop/mobile before consolidating principles. Reuse visual-system.md scene evidence and test all available situations on shorter pages. Resolve semantic wording under G1 locks, then develop the whole page in its section loop. Approved CMPs govern construction. After independent design-review, show the complete proposal once and record actual approval/delegation via confirm_design; never invent a signal.
6. When object, material, transformation, place or viewpoint makes spatial treatment credible, complete `docs/methods/spatial-experience.md`: G3 compares 2D, layered, rendered and interactive media on the same narrative job and freezes the least complex winner; technology then selects and spikes a runtime only if interactive 3D won. G4 produces semantic `SPT-*` states, real assets, fallbacks and state-specific QA. “Premium” never activates 3D, an executor is not a runtime, and fixed scroll percentages are not substitutes for narrative states. Otherwise do not load this conditional method. Select technology and build the complete structural landing with real content. Record desktop/mobile renders.
7. Audit those renders first as one scroll narrative and then by scene. Agent 05 derives the minimum sufficient asset set with `image-decisions.md`, decides `IMAGE | NO_IMAGE` and writes ordered `IH-*` briefs. It then runs a bounded image-production subloop inside `production-plan`: new representative/conceptual raster work defaults to real ChatGPT image generation; authentic media, licensed resources, video and real 3D use their appropriate route. With MCP, generate each declared `IMG-*` through `generate_image`; import external assets honestly. The stage cannot close on briefs alone.
8. Validate declared assets against briefs and approved webpage compositions, integrate, render and independently review. Rejection changes the failed route, not the visual job. Keep bounded production correction. New evidence-led runs have no raster or primary-image quota; legacy contracts retain their requirements. Motion is purposeful, not mandatory: global stillness needs reviewed STATIC intent or an explicit user restriction. Preserve reviewed CMP fidelity and the root-cause correction protocol.
9. When a reference depends on video/HTML interaction, use the installed MengTo extraction skill and translate only its observed temporal principle. When 06 has selected GSAP, use only the relevant installed official GSAP skills for implementation and performance; neither capability chooses the design or runtime.
10. Before delivery, agent 07 runs the registered `jakub-interface-polish` capability once in `FULL` mode on the final loaded-font desktop/mobile renders. It must pass `TEXT_SPACING_CRAFT` with scene-specific evidence for section breathing, paragraph measure/leading, mixed-type optics, wrapping and mobile recomposition. Then run the gate/state checks, deterministic UI scan and `tools/validate_delivery.py`, record the finished design fingerprint and complete `qa-release.md#Final delivery contract` with `docs/methods/final-delivery.md`. The harness must finish `COMPLETE/PASS`, generate `execution-receipt.json` and pass `tools/verify_execution.py`. Only then begin the final response with `AGENTIC WEB DESIGN: VERIFIED` and expose the receipt, concrete package, entry/preview and final-render paths plus status, exact commands and limitations. Otherwise begin with `AGENTIC WEB DESIGN: UNMANAGED`; internal documents or verbal claims are not proof.

Images representing real people, premises, clients or results require authentic supplied media. Generated imagery may represent concepts, atmosphere, materials and non-documentary scenes without pretending to be evidence.

When a tool or correction fails twice, stop with valid work preserved and explain what is needed to continue.

Write only inside the user-approved local project and implementation roots. Publishing, pushing or writing to GitHub or any external service requires an explicit user request.

For MCP setup, supported static exports, image provenance, fresh review and delivery tools, use `docs/architecture/managed-runtime.md`. The canonical route is `start_landing`, the returned stage packet, required tools, `advance_stage` and final `verify_run`. For a headless executor use `doctor`, `init` and active `run`. The low-level `chat-start`/`chat-next` route controls order but does not itself supply generation or an independent reviewer. Never treat an initialized folder or manually injected event log as an executed test.
