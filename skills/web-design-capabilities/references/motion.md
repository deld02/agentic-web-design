# Motion craft capability

Activate when the selected `FX-*` uses motion to communicate hierarchy, state, spatial relation, feedback or brand character. This capability refines the winner rather than deciding whether exploration happens.

For every material opportunity compare a static `NONE` baseline, a `SIMPLE` intervention and an `EXPRESSIVE` candidate as defined in `docs/methods/effect-selection.md`. Do not treat the first technically viable effect as selected.

For each motion define purpose, trigger, enter/exit behavior, duration/easing or spring rationale, interruption behavior, device constraints, reduced-motion alternative and performance risk.

Prefer:

- quick, responsive repeated interactions;
- transitions that can retarget for interactive states;
- transforms and opacity when they express the intended behavior;
- origin-aware popovers and restrained press feedback;
- CSS/WAAPI for predetermined motion when appropriate;
- a prototype when runtime behavior is uncertain.

Do not animate because empty space feels unfinished. Do not make global library rules: the approved mechanism and selected stack decide implementation.

Record adopted and rejected motion opportunities in `production-plan.md`; final findings go to `qa-release.md`.
